# Session-as-Route Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make each session a distinct hash route (`#/session/<ulid>`) so the existing sidebar forward/back arrows traverse session history.

**Architecture:** The route param becomes the single source of truth for the active session. A new `routes/session.$sessionId.tsx` route renders `TasksView` and syncs the param into the existing Zustand `selectedSessionId` via an effect, so every existing consumer of `selectedSessionId` stays unchanged. `/` becomes an empty welcome state. Session switching, creation, and deletion go through `navigate()` so they enter the history stack.

**Tech Stack:** React, TanStack Router (`createHashHistory`), Zustand, React Query, Vitest (jsdom for renderer), Biome.

**Spec:** `docs/superpowers/specs/2026-06-16-session-routing-design.md`

**Conventions:**
- Run tests with `npm test` (runs under Electron's node — do NOT use bare `npx vitest`).
- Run a single test file: `npm test -- src/renderer/src/lib/session-nav.test.ts`
- Format a touched file: `npx biome check --write <file>` (do NOT run `npm run check` — it reformats the whole repo).
- `routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin during `electron-vite dev`/`build`; never hand-edit it.

```ts
// src/renderer/src/lib/session-nav.ts
import type { SessionSummary } from '@shared/types/ui'

/**
 * After deleting `deletedId`, the session id to navigate to: the most
 * recently active remaining session, or null if none remain.
 */
export function pickNextSession(sessions: SessionSummary[], deletedId: string): string | null {
  const remaining = sessions.filter((sn) => sn.id !== deletedId).sort((a, b) => b.lastActiveAt - a.lastActiveAt)
  return remaining[0]?.id ?? null
}
```

### Task 4: Session route + sync effect

New route `#/session/$sessionId` renders `TasksView`, syncs the param into the store, hydrates, and redirects to `/` for unknown ids.

**Files:**
- Create: `src/renderer/src/routes/session.$sessionId.tsx`

- [ ] **Step 1: Create the route**

```tsx
// src/renderer/src/routes/session.$sessionId.tsx
import { createFileRoute, useNavigate } from '@tanstack/react-router'
import { useQueryClient } from '@tanstack/react-query'
import { useEffect } from 'react'

import { TasksView } from '@/components/views/tasks-view'
import { hydrateSession } from '@/hooks/use-tasks'
import { useSessionsStore } from '@/stores/sessions'

export const Route = createFileRoute('/session/$sessionId')({ component: SessionView })

function SessionView(): React.JSX.Element {
  const { sessionId } = Route.useParams()
  const qc = useQueryClient()
  const navigate = useNavigate()
  const select = useSessionsStore((s) => s.select)
  const sessions = useSessionsStore((s) => s.sessions)

  // The URL is the source of truth; mirror it into the store and hydrate the
  // session's tasks. Every existing consumer keeps reading selectedSessionId.
  useEffect(() => {
    select(sessionId)
    void hydrateSession(qc, sessionId)
  }, [sessionId, select, qc])

  // Unknown id (stale hash / deleted elsewhere): once the list has loaded and
  // does not contain it, fall back to the empty state.
  useEffect(() => {
    if (sessions.length > 0 && !sessions.some((s) => s.id === sessionId)) {
      void navigate({ to: '/' })
    }
  }, [sessions, sessionId, navigate])

  return <TasksView />
}
```
