## §1 Goals & Non-Goals

**Goals**

- Rebuild `src/renderer/src/` from scratch to match `sage-ai-template/frontend/src/` structure.
- Adopt the full template stack: TanStack Router/Query/Table, zustand, shadcn/ui (base-nova preset), lucide-react, sonner, next-themes, vaul, cmdk, cva, dnd-kit, recharts, embla, date-fns, etc.
- Initial route table: `/` (Tasks), `/settings` (placeholder), `/skills` (placeholder), with left sidebar navigation.
- Theming: light / dark / system via `next-themes`.
- Migrate all five existing hand-written components (`TitleBar`, `TaskInput`, `TaskList`, `TaskTimeline`, `PermissionSheet`) onto shadcn primitives.
- IPC contract unchanged: renderer keeps talking to main via `window.swarm.*` (preload bridge untouched).

**Non-Goals**

- No changes to `src/main/`, `src/worker/`, `src/shared/`.
- No changes to IPC schema (`InboundSchema`, `OutboundSchema`).
- No real Settings/Skills functionality — placeholder views only (scaffold + sidebar entries).
- No HTTP calls. `ky` is added as a dependency but not used; TanStack Query is wired via an IPC adapter.
- No changes to main-process windowing / IPC behavior. macOS TitleBar draggable region behavior preserved.

## §4 Routing (Electron specifics)

TanStack Router's default `createBrowserHistory()` does not work under `file://` in Electron production builds. We use **hash history** so reload-during-dev preserves the current route.

```ts
// main.tsx
import { createRouter, createHashHistory } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

const router = createRouter({
  routeTree,
  history: createHashHistory(),
  defaultPreload: 'intent',
})

declare module '@tanstack/react-router' {
  interface Register { router: typeof router }
}
```

**Build integration:** add `@tanstack/router-plugin/vite` to the `renderer` segment of `electron.vite.config.ts`. The plugin scans `src/renderer/src/routes/` and rewrites `routeTree.gen.ts` on dev/build.

**Devtools:** `TanStackRouterDevtools` mounts only when `import.meta.env.DEV`.

**Layout (chosen Option B from brainstorming):**

```
┌──────────────┬────────────────────────────────────────┐
│ 🔴🟡🟢 ☰    │ ░ TitleBar continues over to the right ░ │
├──────────────┤  (full-width draggable region)         │
│ ▸ Tasks  ●   │ Main content (<Outlet/>)               │
│ ▸ Settings   │                                        │
│ ▸ Skills     │ ...                                    │
│              │                                        │
│ Theme: 🌙    │                                        │
└──────────────┴────────────────────────────────────────┘
```

`-webkit-app-region: drag` is applied to the row containing the TitleBar; interactive children (sidebar toggle button, etc.) opt back out via `-webkit-app-region: no-drag`.

## §5 State Architecture & Data Flow

Two state sources, with a clear split:

| Kind | Owner | Examples |
|---|---|---|
| Events accumulated from worker / task list | **TanStack Query cache** (`['tasks']`) | `tasks`, per-task events, summary |
| Pure client UI state | **zustand `useUiStore`** | sidebar collapsed, `selectedTaskId` |
| Pending user-decision queue | **zustand `usePermissionStore`** | `queue` FIFO |

**Why tasks live in Query, not zustand:** even though there is no HTTP, worker events behave like server state — they have a remote source, freshness/staleness semantics, and benefit from cache invalidation patterns. Query gives this for free; reimplementing in zustand re-invents cache.

### `lib/api.ts`

Imports use the existing `@shared` alias (already configured for the renderer in `electron.vite.config.ts` and `tsconfig.web.json`), not deep relative paths.

```ts
import type { UIEvent } from '@shared/types/ui'

export const swarmApi = {
  submitGoal: (goal: string): Promise<void> =>
    window.swarm.submitGoal(goal),
  decidePermission: (
    actionId: string,
    decision: 'grant' | 'deny' | 'skip',
  ): Promise<void> =>
    window.swarm.decidePermission(actionId, decision),
  subscribeEvents: (cb: (e: UIEvent) => void): (() => void) =>
    window.swarm.subscribeEvents(cb),
}
```

### `lib/apply-event.ts`

Pure reducer extracted verbatim from the current `App.tsx` `reducer()` body. Takes `(tasks: TaskRecord[], event: UIEvent)` → `TaskRecord[]`. Single-source-of-truth for event-folding logic; covered by unit tests.

### `hooks/use-events-subscription.ts`

A single top-level effect hook called once from a `<EventsBridge/>` placed in `__root.tsx`:

```ts
function useEventsSubscription(): void {
  const qc = useQueryClient()
  const pushPermission = usePermissionStore((s) => s.push)
  useEffect(() => {
    return swarmApi.subscribeEvents((e) => {
      qc.setQueryData<TaskRecord[]>(['tasks'], (prev = []) => applyEvent(prev, e))
      if (e.kind === 'task.permission_request') pushPermission(buildPrompt(e))
    })
  }, [qc, pushPermission])
}
```

### `hooks/use-tasks.ts`

```ts
export const useTasks = (): TaskRecord[] =>
  useQuery({ queryKey: ['tasks'], queryFn: () => [] as TaskRecord[], staleTime: Infinity }).data ?? []

export const useSubmitGoal = () =>
  useMutation({ mutationFn: swarmApi.submitGoal })

export const useDecidePermission = () => {
  const remove = usePermissionStore((s) => s.remove)
  return useMutation({
    mutationFn: ({ actionId, decision }: { actionId: string; decision: PermissionDecision }) =>
      swarmApi.decidePermission(actionId, decision),
    onSuccess: (_, { actionId }) => remove(actionId),
  })
}
```

`queryFn` is a stub returning `[]` — the cache is only ever updated by `setQueryData` from `useEventsSubscription`. `staleTime: Infinity` prevents auto-refetch (there is nothing to refetch).

### zustand store shape

```ts
// stores/permission.ts
export const usePermissionStore = create<{
  queue: PermissionPrompt[]
  push: (p: PermissionPrompt) => void
  remove: (actionId: string) => void
}>((set) => ({
  queue: [],
  push: (p) =>
    set((s) =>
      s.queue.some((x) => x.actionId === p.actionId) ? s : { queue: [...s.queue, p] },
    ),
  remove: (id) => set((s) => ({ queue: s.queue.filter((x) => x.actionId !== id) })),
}))

// stores/ui.ts
export const useUiStore = create<{
  selectedTaskId: string | null
  setSelected: (id: string | null) => void
}>((set) => ({ selectedTaskId: null, setSelected: (id) => set({ selectedTaskId: id }) }))
```

### Selector rule

Always use narrow selectors so a component only re-renders when its slice changes:

```ts
// Correct
const queue = usePermissionStore((s) => s.queue)
// Incorrect (re-renders on any store update)
const { queue } = usePermissionStore()
```

## §6 Theming

**Provider chain (`main.tsx`):**

```
StrictMode
  └─ QueryClientProvider
       └─ ThemeProvider (next-themes; attribute="class", defaultTheme="system", enableSystem, disableTransitionOnChange)
            └─ TooltipProvider
                 └─ RouterProvider
```

**`styles/globals.css`:** generated by `shadcn init` and edited as needed. Holds `:root` (light) and `.dark` CSS variable sets, plus `@theme inline` mapping to Tailwind v4 color tokens.

**Toggle (`components/theme-toggle.tsx`):** wraps `next-themes`'s `useTheme()` in a shadcn `Select` (`light`/`dark`/`system`). Surfaced in `SettingsView` and (optionally) `<SidebarFooter>`.

**Flash prevention:** `next-themes` already injects the head script that reads localStorage on first paint, before React hydrates.

**System follow:** `next-themes` listens to `prefers-color-scheme`. macOS Appearance changes propagate automatically through Electron's `nativeTheme` to the renderer's media query without main-process intervention.

## §7 shadcn Install Procedure (base-nova kitchen-sink)

**Why this section is standalone:** the base-nova preset is a kitchen-sink that produces ~10 side effects when first installed; a "trust the CLI" approach leaks lint warnings and broken components into the tree. Procedure below is the deterministic alternative.

**Prerequisite:** all §2 dependencies installed first (especially `@base-ui/react`, `tw-animate-css`, `class-variance-authority`, `lucide-react`, `tailwind-merge`).

**Steps:**

1. Drop a `components.json` at `src/renderer/components.json` (mirrors template, since shadcn CLI resolves all paths relative to this file's parent directory). Run shadcn commands with `--cwd src/renderer`.

   ```json
   {
     "$schema": "https://ui.shadcn.com/schema.json",
     "style": "base-nova",
     "rsc": false,
     "tsx": true,
     "tailwind": {
       "config": "",
       "css": "src/styles/globals.css",
       "baseColor": "neutral",
       "cssVariables": true
     },
     "aliases": {
       "components": "@/components",
       "utils": "@/lib/utils",
       "ui": "@/components/ui",
       "lib": "@/lib",
       "hooks": "@/hooks"
     },
     "iconLibrary": "lucide"
   }
   ```

2. `pnpm dlx shadcn@latest init -y --cwd src/renderer`. Inspect `git diff biome.json` immediately afterward.

3. `pnpm dlx shadcn@latest add --all --cwd src/renderer`.

4. **Review checklist** — fix all of these before committing:

   | Known side effect | Fix |
   |---|---|
   | `biome.json` `useIgnoreFile: true` injected | Revert to `false` or add a `src/renderer/.gitignore` |
   | `biome.json` `domains.next: recommended` / `@prime-next/**` residue | Delete |
   | `biome.json` `src/components/ui/**` ignore path | Rewrite to `src/renderer/src/components/ui/**` |
   | Stray `paths` added to root `tsconfig.json` / `tsconfig.node.json` | Revert — the real `paths` live in `tsconfig.web.json` |
   | `calendar.tsx` ships react-day-picker v9 classNames (`table`, etc.) | Rewrite to v10 (`month_grid`) |
   | Duplicate `tw-animate-css` import lines | Keep only the one in `globals.css` |
   | Old `index.css` orphan | Delete |

5. **Demo components are kept but unused.** Files such as `dashboard.tsx`, `data-table.tsx`, `section-cards.tsx`, `chart-area-interactive.tsx`, `nav-documents.tsx`, `nav-secondary.tsx`, `nav-user.tsx` are not in `components/ui/` and may land outside it during install. They are not deleted — they document patterns we may use later — but `__root.tsx` does not import them.

6. **Rewrite `app-sidebar.tsx`** to a minimal Tasks/Settings/Skills nav. Template's version is dashboard-flavored.

7. **Verify:** `pnpm typecheck && pnpm lint && pnpm test`. Lint must be zero errors before this commit lands. Warnings on `components/ui/**` are excluded by the Biome ignore path above.

```tsx
// tasks-view.tsx
export function TasksView() {
  const tasks = useTasks()
  const queue = usePermissionStore((s) => s.queue)
  const selectedTaskId = useUiStore((s) => s.selectedTaskId)
  const selected = tasks.find((t) => t.id === selectedTaskId) ?? tasks[0]
  const submitGoal = useSubmitGoal()
  const decide = useDecidePermission()

  return (
    <div className="flex h-full flex-col">
      <TaskInput
        disabled={submitGoal.isPending}
        onSubmit={(g) => submitGoal.mutate(g)}

      <PermissionSheet

        onDecide={(actionId, d) => decide.mutate({ actionId, decision: d })}

  )
```
