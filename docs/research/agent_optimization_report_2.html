📋 01

系统概述（Executive Summary）

概览SwarmAgents 是一个基于 Electron 的多 Agent 协作桌面应用，内置 24 个预定义 Agent，分布在 9 个团队中。系统已具备自我校验机制（硬检查 + LLM 软判决双循环验证）。本报告基于全网最优秀的 Agent 实现文章研究，为每个 Agent 提供 Prompt 优化建议、Skills 映射方案和自校验增强指南。

🏗️ 多 Agent 架构核心

24 个 Agent 分布在 9 个职能团队，支持委派、协调、并行执行与跨团队集成。

🛡️ 双层自校验已实现

硬检查（确定性）+ 软检查（LLM 判官）双循环验证，支持 gap 反馈与重新提示。

🧩 Skill 体系7 Skills

内置 7 个 Skill（浏览器、调研、架构图、MCP 管理等），可按 Agent 角色映射加载。

🛡️ 06

自校验架构（Self-Verification Architecture）

系统已在 verify.ts 中实现双层自校验机制。本节分析现有架构并提出 5 项增强建议。

✅ 当前机制（已实现）

1. 硬检查（Hard Checks）确定性

完全确定性验证，无 LLM 参与，可信度最高。

  • command 类型：运行 shell 命令，检查退出码和 stdout
  • file_exists 类型：检查文件是否存在
2. 软检查（Soft Checks）LLM 判官

对没有可执行检查的条件，使用 LLM 作为裁判。

  • 解析 LLM 输出中的 {pass: boolean, gaps: string[]} JSON
  • 灵活但非确定性，适合判断性条件
3. 验证循环（Verify Loop）迭代改进

runGoalVerifyLoop：验证→如有 gap 则重新提示→再次验证。

  • 最多 maxRounds 轮（默认从 acceptance criteria 数量推导）
  • 支持 budget 短路（turn 失败/取消则直接失败）
// 验证循环简化示意（verify.ts）
while (round < maxRounds) {
  const result = runVerification(criteria);  // 硬检查 + 软检查
  if (result.allPass) return SUCCESS;
  const reworkGoal = buildReworkGoal(result.gaps);  // 注入 gap 反馈
  delegate(reworkGoal);  // 重新提示 Agent 修复
  round++;
}
return FAIL;  // 超过轮次上限

⚡ 优化建议

1
⭐ 引入 Reflexion 模式
来源：Reflexion 论文 (NeurIPS 2023)

在验证失败后，Agent 应生成结构化的"反思"而非简单重试。存储反思到记忆缓冲区（remember / recall），避免重复错误。实现方式：在 verify loop 的 rework goal 中注入上一轮的 gaps 和反思建议。

2
⭐ 添加分层置信度评分
来源：Galileo Self-Evaluation

硬检查 = 高置信度（确定性通过）；软检查 = 中置信度（LLM 判定通过）；无检查条件 = 低置信度（纯判断）。在最终报告中显示置信度等级。

3
⚠️ 警惕 Self-Critique Paradox
来源：Snorkel AI

对于简单任务（高基线成功率），自校验循环反而可能降低性能。建议：为简单任务设置 maxRounds=1（仅验证一次）；为复杂任务设置 maxRounds=3-5（允许多次改进）。

4
增加 Pre-Verification（提交前自检）
来源：SWE-agent ACI 概念

在 Agent 完成工作但提交前，添加一个"烟雾测试"步骤——让 Agent 自己运行快速验证。例如：工程师 Agent 在报告前先运行 typecheck + lint + 快速测试。

5
增加 Acceptance Criteria 自动生成
来源：本报告行动项

CEO 在委派时自动为每个团队 head 生成 acceptance criteria，使用 set_acceptance_criteria 将目标转化为可检查条件。这使验证循环从一开始就有明确的通过/失败标准。
