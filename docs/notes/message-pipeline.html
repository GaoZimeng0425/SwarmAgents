并行流：事件如何到前端
主流程里每次 emit() 都同时做三件事——这是异步并行的，不阻塞 LLM 循环：

↓ ① 持久化

关键点
主流程（LLM 循环）和事件流是解耦的。

LLM 在跑 → 边跑边 emit → 前端边收边渲染。
用户看到的是实时流式更新，不是等 LLM 全跑完才显示。

事件先写 SQLite（崩溃不丢），再推前端（挂了不影响 engine）。
全流程一句话串起来：
用户打字 → IPC → submitPrompt → launchMessage（排队 + 拿槽位）→ engine.run（LLM 循环）→ LLM 要么直接回复（分支 A），要么调工具（分支 B）→ 工具里最特殊的是 delegate，它会递归启动一整个子 run（和父走一样的流程）→ 全程每个节点 emit 事件 → 写库 + 推前端 → 用户看到实时更新。

三个并发管控点（图中步骤 ③④ + delegate 的 withSlotReleased）：
• waitTurn：同 session 内 FIFO，消息排队不抢
• acquireSlot：全局并发池，限制同时跑的 run 数量
• withSlotReleased：父 delegate 子时让出自己的槽位，避免满池父 run 互相卡死
