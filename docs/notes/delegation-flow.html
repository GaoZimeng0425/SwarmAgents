Agent 委托流程

一个 Leader 怎么把任务交给子 Agent，结果怎么回来

Leader（主 Agent）
Child（子 Agent）
事件 / 存储
UI 可视化
1
Leader 制定计划
调用 set_delegation_plan 工具
记录任务拆分：[d1: 查资料, d2: 写报告, d3: 审核]
保存到 planState + 发出 delegation_plan 事件
2
编排图出现
前端收到 delegation_plan 事件
画布上出现 3 个灰色方块（pending 状态）
方块之间有依赖箭头（dependsOn）
Leader 开始执行，调用 delegate 工具
3
Leader 委派 d1
调用 delegate({ prompt: "查资料", itemId: "d1" })
带上 itemId 告诉系统"这是 plan 里的 d1"
d1 标记为蓝色（running）· 启动子 Agent
━━ 子 Agent 运行（child run）━━
4
子 Agent 干活
独立的 LLM 对话循环
有自己的工具（读写文件、搜索等）
自动注入了 report_result 工具
任务完成
5
子 Agent 提交结构化结果
调用 report_result({ artifacts: [...] })
不只是写文字总结，还提交机器可读的产出物
run 结束，结果向上传递
6
d1 变绿 + 结果归档
三件事同时发生：
① 发出 delegation_update 事件 → 编排图 d1 变绿色
② artifacts 存入 planState → session 级保存（跨轮不丢）
③ artifacts 塞进 tool_result → Leader 直接读
Leader 拿到结果，继续委派下一个
7
Leader 委派 d2、d3…
重复步骤 3-6，编排图实时更新
每个 item 从 灰(pending) → 蓝(running) → 绿(completed)
全部完成后
8
用户可以 Fork
在任意已完成的对话消息上 hover
点击"从这里分支" → 输入新指令
系统从那个时间点复制对话历史，开一个新 session
一句话总结
Leader 拆任务（plan）→ 逐个委派给子 Agent（delegate）→ 子 Agent 干完提交结构化结果（report_result）→ 结果同时给 Leader 用（artifacts）和给用户看（编排图）→ 全程事件持久化，随时可以 Fork 重跑
